# Оплаты вне Synoro

Многие клиенты платят специалисту напрямую: наличными на приёме, переводом
по СБП, картой на терминал. Раньше Synoro о них не знал. У пакета,
начисленного вручную, не было суммы. Записи с оплатой на приёме
(`docs/pay-at-visit.md`) никак не отмечались оплаченными. Аналитика
показывала только онлайн-оплаты, и посчитать доход за месяц для налоговой было
не по чему. Теперь эти деньги записываются.

## Что видит специалист

Раздел «Оплаты» (`/practices/<id>/payments`) — у владельца и администраторов:

- **«Ждут оплаты»** — прошедшие за 90 дней записи с оплатой на приёме, по
  которым оплата ещё не отмечена (`offlinePayment.unpaid`). Кнопка «Оплачено»
  открывает «Внести оплату» для этой записи. Пока таких записей нет, раздела
  тоже нет.
- **«Оплаты вне Synoro»** — последние 100 оплат и сумма за 30 дней. «Внести
  оплату» — для любого клиента, без записи. Ошибочную оплату можно удалить.
- **«Онлайн-оплаты»** — платежи через ЮKassa и Т-Банк, как раньше.
- Владелец скачивает **«Доходы за период»** — CSV для декларации: онлайн-оплаты
  и оплаты вне Synoro по дням поступления.

В карточке клиента «Начислить» получил необязательное поле «Сколько заплатил
клиент». С суммой начисление записывает и оплату (`credit.grant` с
`payment`), одной транзакцией.

Аналитика («Про», владелец) показывает «Доход»: онлайн плюс вне Synoro, с
разбивкой в описании графика.

## Как устроено

`offline_payments`: `practice_id`, `member_id` (клиент), `booking_id` (запись,
если оплачена на приёме), `credit_entry_id` (начисление, если это пакет),
`amount` (копейки, 1 ₽ – 1 000 000 ₽), `method` (`cash`, `transfer`, `card`,
`other`), `paid_at`, `note`, `created_by_id`.

- Оплата сама баланс не меняет. Пакет начисляет `credit.grant`, а запись
  с оплатой на приёме ничего с баланса и не брала.
- Одна запись оплачивается один раз (`ALREADY_PAID`). Проверка идёт под
  блокировкой строки записи, поэтому двойное нажатие не создаст две оплаты.
- Удаление (`offlinePayment.remove`) убирает только запись о деньгах.
  Начисленное остаётся на балансе, а запись возвращается в «Ждут оплаты».
- «Ждут оплаты» — это `kind = consultation`, `credits = 0`, активная, без
  `hold_until`, с клиентом-аккаунтом, закончилась, без оплаты. Старые
  консультации получили `credits = 1` при переходе на услуги, поэтому сюда не
  попадают. Импортированные записи без аккаунта — тоже.

## API

`offlinePayment.*` (`packages/api/src/routers/offline-payment/`), сотрудники:

- `record({ practiceId, bookingId? | memberId?, amount, method, paidAt, note? })`;
- `list({ practiceId })` — последние 100 и `month: { amount, count }`;
- `remove({ practiceId, paymentId })`;
- `unpaid({ practiceId })`.

`credit.grant` принимает `payment: { amount, method, paidAt, note? }` только
при `delta > 0` (иначе `PAYMENT_WITHOUT_GRANT`). `data.exportPart` умеет
`what: "income"` с периодом.

## Выгрузка

Полный архив кладёт оплаты в `data.json` (`offline_payments`,
`docs/data-format.md`) и в `payments.csv` строками «Оплата клиента вне
Synoro». Импорт архива их пока не переносит.

## Чего нет

- Чеков: Synoro их не пробивает. Самозанятый формирует чек в «Мой налог»,
  а ИП — на своей кассе.
- Долга за позднюю отмену записи с оплатой на приёме.
- Отметки оплаты прямо в календаре — только из «Ждут оплаты».
