# Рабочие заметки по клиенту

Психолог ведёт записи по каждому клиенту: запрос, о чём говорили, о чём
договорились, что проверить в следующий раз. Без этого он держит вторую
систему (Notion, бумага) рядом с расписанием. Заметки собирают эти записи в
карточке клиента, рядом с его записями и балансом.

## Как работает

- **Где.** Карточка клиента в разделе «Клиенты» (`/practices/<id>/clients`),
  вкладка «Заметки». Заметка бывает «о клиенте в целом» или к одной из его
  встреч, которая уже началась (`note.sessions`: все, сколько бы ни прошло,
  включая неявки и отмены, без неоплаченных броней). У прошедшей встречи на вкладке «Записи» есть
  кнопка «Написать заметку»: она открывает «Заметки» с этой встречей.
- **Кто.** Только владелец практики, лично. Администраторы практики заметок
  не видят: ни вкладки, ни процедур (`FORBIDDEN`). Администратор Synoro, вошедший
  под владельцем, тоже не видит (`session.impersonatedBy`): страница клиентов
  передаёт карточке `canKeepNotes`. В демо заметки
  работают, но демо-аккаунт общий, а ночной сброс стирает всё.
- **Что.** Текст до 10 000 символов (`clientNoteBodySchema`). Заметку можно
  исправить и удалить; корзины нет. Встречу, к которой привязана заметка,
  потом не поменять.
- **Тариф.** Любой. Платная граница проходит по деньгам и команде
  (`docs/pricing-strategy.md`), а заметки удерживают специалиста.

## Хранение

`client_notes`: `practice_id`, `member_id` (клиент с кабинетом), `booking_id`
(встреча, `set null` при её удалении), `body`, `author_id`, даты.

- `body` зашифрован AES-256-GCM ключом `PAYMENTS_SECRET_KEY`
  (`encryptSecret` / `decryptSecret` из `@synoro/config/secrets`): в дампе
  базы и бэкапах текста нет. Без ключа процедуры отвечают `UNAVAILABLE`.
  Ключ теперь защищает и заметки: менять его без перешифровки нельзя.
- Клиент ушёл из практики (строка `practice_members` удалена) — его заметки
  удаляются вместе с ним.
- Карточки из импорта (`practice_clients`) заметок пока не имеют: у них есть
  только поле `note`.

## API

`note.*` (`packages/api/src/routers/note/`), все — владелец, лично:

- `list({ practiceId, memberId })` — новые сверху, с `bookingStartsAt`.
- `sessions({ practiceId, memberId })` — встречи клиента, к которым можно
  написать заметку, новые сверху (до 200).
- `create({ practiceId, memberId, bookingId?, body })` — клиент и встреча
  должны быть этой практики, встреча — этого клиента (`NOT_FOUND`).
- `update({ practiceId, noteId, body })`, `remove({ practiceId, noteId })`.

## Выгрузка

Полный архив (`docs/data-export.md`) кладёт заметки в `data.json` в открытом
виде, в массив `notes` (`docs/data-format.md`). Таблицы CSV и еженедельная
копия клиентов их не содержат. Импорт архива заметки пока не переносит.

## Перед запуском

Пункт 4.4 Условий (`apps/web/src/app/legal/terms`) прямо говорит, что Сервис
«не предназначен для ведения … психотерапевтической документации». Пункт 3.1
Политики говорит, что специальные категории данных не обрабатываются. Заметки
психолога часто содержат сведения о здоровье. Прежде чем открывать функцию,
юрист должен:

- переписать эти пункты;
- описать в разделе 9 Политики («Как мы защищаем данные») шифрование заметок и
  то, что их видит только владелец.

Вместе с заметками нужен двухфакторный вход для специалиста: сейчас его нет.
