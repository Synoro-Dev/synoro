# Импорт данных

Переезд к нам без ручного перебивания: `/practices/<id>/import`, первый шаг первой
настройки, роутер `import.*`, код в `packages/jobs/src/data-import`. Только владелец
практики, сам (`dataProcedure`, как у экспорта). Администраторы видят только сами
карточки.

## Карточки вместо аккаунтов

Импортированный клиент — строка `practice_clients`, а не пользователь. Создавать
пользователей нельзя: у многих нет почты, а главное, чужой адрес в файле привязал бы
чужой аккаунт к практике, и его владелец показал бы свой телефон её сотрудникам.
Поэтому `addMember` только приглашает, и импорт тоже никого не присоединяет.

Отсюда же главное требование: **импортированные клиенты не получают ничего**. Рассылки
ходят через соединение с `practice_members`, у карточки его нет, и импорт не ставит
писем в очередь. Это закреплено тестами. Новая рассылка должна идти через аккаунты.

Если человек с карточкой сам запишется, у него появится аккаунт отдельно от карточки:
автоматически они не связываются, потому что неподтверждённая почта ничего не
доказывает, а на карточке может быть баланс.

## Шаги

1. **`import.upload`**: файл до 10 МБ, тип определяется по байтам, а не по имени.
   Файл лежит в `import_files` рядом со строкой партии (`import_batches`) и удаляется
   через 7 дней или при отмене. Содержимое не логируется.
2. **`import.preview`**: сопоставление колонок, ничего не пишет. Показывает новых,
   повторы (по телефону, затем по почте, с теми, кого практика знает, и внутри файла)
   и строки с ошибками с причиной.
3. **`import.commit`**: пишет частями по 200 строк, каждая в своей транзакции. Больше
   1000 строк уходит в задачу `data-import` с id партии на входе. Повторный запуск
   находит уже записанное как повторы.
4. **`import.undo`**: удаляет то, что партия добавила, и возвращает то, что она
   дописала к существующим карточкам (`import_batch_items`).

Ошибки не останавливают загрузку; `import.rejected` отдаёт такие строки таблицей с
колонкой «Ошибка», чтобы исправить и загрузить снова.

## Чтение файлов

Кодировка: BOM, затем строгий UTF-8, иначе Windows-1251. Разделитель: тот из `; , таб |`,
что даёт больше колонок на большинстве строк. XLSX читается регулярными выражениями
поверх `fflate`, а не XML-парсером: из файла читаются только ячейки, поэтому он не может
ничего подгрузить или развернуть. Размер после распаковки ограничен 100 МБ заранее.

Заметки по умолчанию не переносятся: Synoro не предназначен для медицинских записей
(п. 3.1 политики), а в чужих таблицах они часто есть.

## Клиент oRPC

Не называйте процедуры `apply`, `call` или `bind`: клиент устроен как прокси поверх
функции, и `orpc.x.apply` вернёт `Function.prototype.apply`. Типы этого не видят, поэтому
такая ошибка всплывает только в браузере.
